# 企业级 Harbor Agent Rollout 平台需求规格说明书

**版本：V1.0**  
**日期：2026-10-05**  
**建设方式：推理服务复用 + Harbor Runtime 开源复用 + Sandbox/Hub 自研**

---

# 1. 项目定位

建设一个面向 Agent Eval、Benchmark、数据生产及后续 Agentic RL 的统一 Rollout 平台。

平台不负责重新实现：

- LLM 推理引擎；
- Claude Code / Codex 等 Agent；
- Harbor Trial Runtime；
- Harbor Verifier / RewardKit；
- Harbor Task 基础格式。

平台重点建设：

```text
1. Sandbox Platform
2. Harbor Execution Worker
3. Harbor Hub / Control Plane
4. Rollout Data Platform
5. IAM / Secret / Governance
6. Experiment Analytics
```

最终目标：

```text
Task / Dataset
       ↓
Experiment Job
       ↓
大规模 Trial 调度
       ↓
Sandbox
       ↓
Harbor Runtime
       ↓
Agent
       ↓
内部推理服务
       ↓
Trajectory / Artifact
       ↓
Verifier / Reward
       ↓
Harbor Hub
       ↓
分析 / 数据集 / RL
```

# 5. Sandbox Platform 需求

## 5.1 定位

Sandbox 是 Agent 的“临时计算机”。

Harbor 负责：

```text
怎么运行 Trial
```

Sandbox 平台负责：

```text
在哪里运行 Trial
```

Harbor 本身允许通过继承 `BaseEnvironment` 接入新的 Environment Provider，因此建议开发内部 `InternalSandboxEnvironment` Adapter，而不是修改 Harbor 核心执行逻辑。

---

# 6. Harbor Worker

## 6.1 为什么必须有 Worker

不建议：

```text
Hub
直接 ssh / exec Harbor
```

建议：

```text
Hub
 ↓
Trial Queue
 ↓
Harbor Worker
 ↓
Sandbox API
 ↓
Harbor Runtime
```

Worker 是 Control Plane 与 Runtime 之间的解耦层。

---

## 6.2 Worker 核心职责

```text
领取 Trial
解析 TrialConfig
下载 Task
获取 Model / Agent 配置
获取 Secret
创建 Sandbox
执行 Harbor
实时 Heartbeat
上传 Log
上传 Trajectory
上传 Artifact
上传 Reward
回收 Sandbox
```

---

## 6.3 Worker 注册

### FR-WRK-001 Worker Register

Worker 启动时注册：

```json
{
  "worker_id": "...",
  "version": "...",
  "harbor_version": "0.23.0",
  "capacity": 32,
  "environment_provider": "internal-sandbox",
  "capabilities": []
}
```

---

### FR-WRK-002 Heartbeat

默认：

```text
10~30 秒一次
```

记录：

```text
available_slots
running_trials
cpu
memory
health
version
```

---

### FR-WRK-003 Trial Lease

Worker 领取 Trial 使用：

```text
Lease
```

而非永久 assignment。

例如：

```text
lease_ttl = 60s
```

如果 Worker 掉线：

```text
Lease 过期
→ Trial 回队列
```

因此建议：

### 方案 A：推荐

```text

```


### 方案 B：后期


```text

```


# 16. Attempt 与 Retry 必须分开

这是核心设计。

例如：

```text
attempts = 4
retries = 3
```

意味着：

```text
需要 4 个逻辑样本
```

但每个逻辑样本因为 Infra Error 可执行多次。

不能把：

```text
Retry
```

计算进：

```text
pass@4
```

官方 Hosted Harbor 已明确区分 attempts、retries 与 concurrent trials。

---

# 17. Failure Taxonomy

错误至少分：

| Error Type | 是否自动 Retry |
|---|---:|
| SANDBOX_CREATE_FAILED | 是 |
| SANDBOX_LOST | 是 |
| WORKER_LOST | 是 |
| MODEL_RATE_LIMIT | 是 |
| MODEL_TIMEOUT | 可配置 |
| NETWORK_ERROR | 是 |
| IMAGE_PULL_ERROR | 可配置 |
| AGENT_CRASH | 可配置 |
| AGENT_TIMEOUT | 否/可配置 |
| VERIFIER_ERROR | 是 |
| REWARD_0 | 否 |
| TASK_FAILED | 否 |

核心原则：

```text
Agent 做错题 ≠ Infra Failure
```

# 53. 项目完成判定

平台第一阶段不是以：

```text
“Harbor 能运行”
```

作为完成。

因为 Harbor 本身已经可以运行。

真正完成标准应是：

> 用户不需要登录 Worker、不需要手工执行 Harbor、不需要找本地 JSON 文件，即可从 Portal 创建一个规模化 Agent Experiment，并最终在 Hub 中完成 Trial、Trajectory、Artifact、Reward 的统一查询和分析。

即：

```text
Create
→ Schedule
→ Execute
→ Observe
→ Verify
→ Store
→ Analyze
```

完整闭环。

# 54. 最关键的架构判断

整个项目真正需要自研的核心，不是一个“Harbor Hub 网页”。

而是：

```text
                自研平台
                   │
     ┌─────────────┼─────────────┐
     ▼             ▼             ▼
 Sandbox      Control Plane   Data Platform
     │             │             │
     └─────────────┼─────────────┘
                   ▼
              Harbor Runtime
                   │
               Agent Rollout
```

因此整体定位建议正式命名为：

> **Agent Rollout & Evaluation Platform**

而不是：

> Harbor Hub Clone。

Harbor 只是其中的 **Rollout Runtime**；Sandbox 是执行底座；Hub 是控制面；Trajectory/Artifact/Reward 才是长期的数据资产。
